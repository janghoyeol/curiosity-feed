# curiosity-feed

> 평소엔 궁금하지 않았지만, 보는 순간 "오 그거 궁금한데?"가 되는 정보를 모아서 보여주는 큐레이션 피드.

## 한 줄 정의

커뮤니티에서 사람들이 쓴 질문을 찾아다니는 대신, 위키백과 DYK·공공데이터·뉴스 같은 **원재료**에서 AI가 직접 "궁금해지는 질문"을 뽑아내고 흥미도를 평가해 피드로 정렬해주는 서비스.

## 배경

이전 프로젝트([curiosity-teacher](https://github.com/janghoyeol/curiosity-teacher))는 커뮤니티 게시판(클리앙, 루리웹 등)에서 사용자가 쓴 질문 글을 수집해 흥미도를 평가하는 구조였다. 하지만:

- 다수 커뮤니티가 robots.txt로 AI 크롤러를 명시적으로 차단하거나(디시인사이드, 더쿠 등), Cloudflare 봇 차단(오늘의유머, 퀘이사존)이 걸려 있어 안전하게 수집할 수 있는 소스가 거의 소진됨
- "전용 질문게시판"이 없는 자유게시판은 질문 밀도가 매우 낮아(보배드림, 뽐뿌 등 실측 0~10%), 양질의 데이터를 모으기 어려움
- 사용자가 쓴 질문은 "나 대신 선택해줘"류(예: "K5랑 아반떼 중 뭐가 나을까요?")가 많아, 필터링 자체가 핵심 난제가 됨

그래서 **"질문을 찾기" 대신 "질문을 만들기"**로 방향을 바꿨다. 원재료를 공식 API로 가져오고, AI가 "누구에게나 같은 답이 적용되는 사실형 질문"으로 가공하면 애초에 "그래서 어쩌라고" 문제가 생기지 않는다. 자세한 피벗 배경은 [`docs/decisions/0001-pivot-to-curated-content.md`](docs/decisions/0001-pivot-to-curated-content.md) 참고.

## 파이프라인 (초안)

```
[원재료 수집] 위키백과 DYK / 공공데이터포털 / 네이버뉴스 오픈API (공식 API만 사용)
     │
     ▼
[Gate 1] 중복/저품질 원재료 필터링 (규칙 기반, LLM 호출 없음)
     │
     ▼
[Gate 2] LLM이 "궁금해지는 질문" 생성 + 흥미도 스코어링
     │
     ▼
[피드] 점수 기준 정렬해서 노출
```

## 원재료 소스

| 소스 | 방식 | 비고 |
|---|---|---|
| 위키백과 On this day (영어판) | 공식 REST API | 연결 완료. 한국어판엔 DYK/onthisday 피드가 없어 영어판을 원재료로 쓰고 번역·질문화는 Gate2에서 처리 |
| 공공데이터포털 - 소방청 연간화재통계 | 공식 Open API (키 발급) | 연결 완료. 개별 화재 사건 로우(3만여 건)를 집계해 "흥미로운 사실" 문장으로 변환 후 Gate2에 전달 |
| 네이버뉴스 검색 오픈API | 공식 API (키 발급) | 아직 연결 안 함. 시사성 보완재 |
| 나무위키 트리비아 | — | **자동 수집 안 함.** CC BY-NC-SA(비영리) + 유사서비스 금지 약관으로 소재 아이디어만 수동 참고 |

## 상태

Gate1(중복/품질 필터) + Gate2(생성+평가 2단계 LLM, Groq) 파이프라인 동작 확인.
소스 2개(위키백과 On this day, 소방청 화재통계) 연결 완료, end-to-end로
`/ingest/*` → `/process/gate2` → `/feed` 흐름 실제 검증됨. 프론트엔드는 아직 없음.

### 로컬 실행

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env  # GROQ_API_KEY, DATA_GO_KR_FIRE_SERVICE_KEY 채우기
.venv/bin/uvicorn app.main:app --reload
```
