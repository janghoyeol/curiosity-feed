# 0001. 커뮤니티 질문 수집 → 원재료 큐레이션으로 피벗

## 상태

승인됨 (2026-10-28)

## 배경

이전 프로젝트 curiosity-teacher는 커뮤니티 게시판(클리앙, 루리웹, 보배드림 등)에서
사용자가 작성한 질문 글을 수집하고, Gate1(규칙 기반 1차 필터) → Gate2(LLM 흥미도 평가)
파이프라인으로 양질의 질문만 걸러내는 구조였다.

실제로 운영하면서 아래 문제가 쌓였다:

1. **소스 고갈**: 디시인사이드, 더쿠, 개드립, FM코리아, 네이트판 등 주요 커뮤니티가
   robots.txt에 `ClaudeBot`/`anthropic-ai` 를 명시적으로 차단. 오늘의유머, 퀘이사존,
   웃긴대학은 Cloudflare 봇 챌린지로 막혀 있음. 레딧은 비인증 `.json` API 접근 자체가
   네트워크 보안 차단에 걸림(사용자 본인 IP에서도 재현). 모두 "우회하지 않는다"는
   원칙상 포기.
2. **질문 밀도 문제**: "전용 질문게시판"이 없는 일반 자유게시판(보배드림, 뽐뿌,
   다나와 DPG)은 실제 배치 테스트에서 질문 밀도가 0~10% 수준으로 극히 낮음.
3. **"나 대신 선택해줘" 문제**: 사용자가 실제로 쓴 질문은 본인 예산/소유물에만
   맞는 개인적 선택 질문("K5랑 아반떼 중 뭐가 나을까요?")이 다수라, Gate2 프롬프트를
   두 차례 다시 다듬어야 했고 여전히 비결정성(동일 입력이 4.0/3.0으로 다르게 나옴)
   문제가 남음.

## 결정

"질문을 찾아다니기"에서 "질문을 만들기"로 구조를 바꾼다.

- 원재료는 위키백과 DYK/On this day, 공공데이터포털·KOSIS, 네이버뉴스 오픈API 등
  **공식 API만** 사용한다. 스크래핑/우회가 필요한 소스는 쓰지 않는다.
- 나무위키 트리비아 섹션은 CC BY-NC-SA(비영리) 라이선스 및 유사 서비스 제작 금지
  약관 가능성 때문에 **자동 수집 파이프라인에 넣지 않고**, 소재 아이디어 발굴용
  수동 참고로만 쓴다.
- LLM의 역할이 "기존 글이 질문인지 분류"에서 "원재료로부터 질문을 생성 + 흥미도
  평가"로 바뀐다. 질문을 직접 만들기 때문에, 설계 단계에서부터 "누구에게나 같은
  답이 적용되는 사실형 질문"만 생성하도록 유도할 수 있어 "나 대신 선택해줘" 문제가
  구조적으로 줄어든다.

## 영향

- 기존 curiosity-teacher 레포(클리앙/루리웹 클라이언트, 질문 탐지 정규식, 커뮤니티
  Gate1/Gate2 코드)는 이 프로젝트에 재사용하지 않는다. 레포를 분리해 새로
  `curiosity-feed`로 시작한다.
- 멀티소스 큐레이션 + AI 스코어링이 핵심 가치임을 README에 명시해, 위키백과 DYK
  하나만으로는 위키백과 대문 기능을 복제하는 것처럼 보일 위험을 피한다.

## 미정 (다음 ADR에서 결정)

- 백엔드/프론트 기술 스택
- Gate1(원재료 중복/품질 체크)의 구체적 규칙
- Gate2 프롬프트 설계
- 데이터 저장 구조
